🎧 lavalink_mixer 플러그인

독립형 Lavalink v4 플러그인 — Lavalink 본체 수정 없이 plugins/ jar 하나로 동작

핵심 한 줄: 앞뒤 무음을 잘라내고, 곡 끝을 기다리지 않고, 겹쳐서 섞고, TTS를 음악 위에 얹는다

1. 이게 뭘 하는 건가? (4가지 기능)

✂️ 앞뒤 무음 스킵leading 무음은 seek으로 점프해서 "내용"부터 재생, trailing 무음은 재생도 크로스페이드도 안 하고 그 지점에서 다음 곡으로
🔗 진짜 Gapless클라이언트 왕복 없이 서버가 직접 다음 곡을 play(). 파일 끝이 아니라 contentEnd = duration − trailingSilence에서 전환
🎚️ 오버랩 크로스페이드들을 수 있는 구간끼리만 equal-power 곡선으로 겹치기. 핸드오프는 정확히 contentEnd에
📢 TTS 오버레이음악은 깔고(ducking) TTS/징글을 위에 믹싱. 끝나면 자동 복구. 길드당 1개씩
예: 5분짜리 곡 끝에 무음이 5초 있으면, 4:55에 다음 곡이 이미 겹쳐 들어오고 4:55 정각에 바톤터치. 무음 5초를 끝까지 듣는 일이 없음.

2. 구조 — 소리 두 개를 하나로 합치는 법

Discord 음성은 연결당 Opus 스트림이 하나뿐이라, 두 번째 소리는 인코딩 전에 섞어야 한다. 그래서 숨은 2번 플레이어를 둔다.

flowchart LR
  Client["봇 (lavalink-client)
1-ahead 예열"] -->|play / filters op| Lavalink["Lavalink 서버"]
  Lavalink --> GM["GuildMixer (길드당 1개)
poll 10Hz / drain 50Hz"]
  GM --> Main["메인 플레이어
음성 연결 O"]
  GM --> Sub["숨은 서브 플레이어
음성 연결 X"]
  Sub -->|SiphonFilter PCM 캡처| Q["SiphonQueue"]
  Q --> F["MixerFilter (메인 체인 말단)
out = main×g + sub×g"]
  Main --> F
  F -->|Opus 인코딩| Discord["Discord 음성"]
  • MixerFilter("mixer")는 볼륨/EQ 뒤, 인코딩 전에 동작. 유휴 시(가중치 1/0)엔 완전 패스스루라서 오버헤드 거의 없음.
  • 서브 플레이어는 디코딩만 하고, 펌프 스레드가 drain()으로 계속 굴려서 PCM을 뽑아낸다.
  • 필터는 길드당 한 번 켜면 된다: {"op":"filters","pluginFilters":{"mixer":{"guildId":"..."}}} (guildId는 문자열!)

  • contentEnd = duration − trailingSilence, start = contentEnd − crossfadeMs (TrimTransition).
  • 뒤로 시크하면 겹치기는 파기된다 (낡은 오버랩 방지). 스트림(길이 무한)은 실시간 감시만으로 절삭.
  • 핸드오프 때는 실제로 믹싱된 샘플 수를 세서 다음 곡 위치를 이어붙인다 (서브 출력 기준).

4. 무음 분석 — pending → ready

sequenceDiagram
  participant B as 봇
  participant S as 서버 (Mixer)
  participant A as 분석 스레드 (서브 플레이어)
  B->>S: POST /mixer/queue/next (B곡)
  S->>S: pending 슬롯에 저장 (hasNext=true, trim=null)
  S->>A: 백그라운드 디코드 + 스캔
  A-->>S: leadMs / trailMs 캐시 (ready)
  Note over S: 전환 시점에 캐시 조회 →
seek(lead) + contentEnd(trail)
  • GET /mixer/state → hasNext:true + nextTrimMs:null = 아직 분석 중. nextTrimMs:[lead,trail]이 보이면 ready.
  • 분석이 전환 시점까지 안 끝나면 무음을 틀지 않고 그냥 넘어간다 (degraded). 그래서 예열은 trackStart 직후 바로 하는 게 좋다.
  • 분석 중엔 서브 플레이어가 바빠서 크로스페이드 시작이 잠깐 미뤄지거나, announce가 409를 낸다 → trim 보이면 재시도.
  • 첫 곡(봇이 직접 play()한 곡)은 예열 슬롯을 안 거쳐서 앞무음 스킵이 안 될 수 있음. 그 뒤부터는 전부 자동.

5. TTS 오버레이 — 음악 깔고 말 얹기

flowchart LR
  M["음악 (메인)"] --> Mix["MixerFilter"]
  T["TTS 클립 (서브)"] --> Mix
  Mix -->|음악은 duckLevel(기본 0.2)로 숙이고
TTS는 페이드인| Discord2["Discord"]
  • POST /mixer/announce {identifier 또는 encodedTrack} → 끝나면 자동 언덕. /mixer/announce/cancel로 강제 중단.
  • 길드당 동시 1개: 크로스페이드 중이거나 분석 중이면 409 → 잠깐 뒤 재시도.

6. 봇 연동 흐름 (lavalink-client)

sequenceDiagram
  participant L as lavalink-client
  participant S as mixer 플러그인
  L->>L: autoSkip=false (필수!)
  L->>S: trackStart(A) → 필터 1회 등록 → preload(B)
  S->>S: A 내용 끝에서 B 자동 시작
  L->>L: trackStart(B) → 큐 동기화(play 전송 금지!) → preload(C)
  L->>L: trackEnd → preload 했으면 무시 + 5초 왓치독
  L->>S: 스킵은 mixer.skip()으로 (슬롯 정리 후 skip)
⚠️ player.skip() 직접 호출 금지 — 낡은 예열이 다음 곡 끝에 엉뚱하게 재생됨. 핸들 mixer.skip(player) 사용. 반복재생(repeatMode)이 켜지면 예열을 쉬고 리피터에게 양보.

7. REST + 설정 치트시트

REST (/mixer/*, 서버와 같은 Authorization)

메서드/경로하는 일
POST /mixer/queue/next다음 곡 예열 {guildId, identifier?, encodedTrack?} (encoded 우선)
DELETE /mixer/queue/next?guildId=예열 취소
GET /mixer/state?guildId=상태 + 설정 (hasNext, nextTrimMs, overlayActive…)
POST /mixer/crossfade겹치기 on/off + 길이 (500–30000ms)
POST /mixer/fade-in곡 시작 페이드인 (0–10000ms, 0=끔)
POST /mixer/announceTTS 오버레이 + 덕킹 (바쁘면 409)
POST /mixer/announce/cancel오버레이 중단
POST /mixer/silence무음 스킵 on/off + 임계값/스캔창 조정

기본 설정 (application.yml → mixer:, 전부 길드별 REST로도 변경 가능)

키기본값의미
crossfadeEnabled / crossfadeMstrue / 5000겹치기 on/off, 겹치는 길이
fadeInMs / maskMs300 / 80곡 시작 페이드 / 핸드오프 이음새 가리개
duckLevel / duckFadeMs0.2 / 300TTS 중 음악 음량 / 복구 속도
silenceSkipEnabledfalse무음 스킵 (트랙당 디코드 1회 추가라 기본 끔)

tailConfirmMs1000실시간 무음이 이만큼 지속되면 절삭 (스트림은 최소 3000)

8. 한계 (숨기지 않음)

  • 크로스페이드는 유한+탐색가능(seekable) 곡만. 스트림은 절삭만 된다.
  • 디코더 예열 수십 ms는 남는다. 완전 제로는 아님.
  • 길드당 서브 소스 1개 (겹치기 vs TTS vs 분석은 서로 기다림).
  • 필터 resetFilters()는 mixer 키를 날린다 → enableMixerFilter() 다시 호출.
